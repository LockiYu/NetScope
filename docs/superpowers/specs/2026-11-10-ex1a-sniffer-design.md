# 实验 1A macOS 网络嗅探器设计

## 1 项目结论

本项目独立实现一款面向 macOS 的图形化网络嗅探器。软件使用 C++17、Qt 6、系统 libpcap 和 CMake，不以跨平台兼容为目标，也不直接调用、包装或修改 Wireshark。项目必须完整实现网络数据包捕获功能，并重点完善网络协议分析、TCP 流追踪、多网卡归并、字段与原始字节联动以及可解释的异常提示。

项目暂定内部名称为 `ex1a-sniffer`。最终提交目录按照课程规定，在获得姓名和学号后改为 `姓名_学号_EX1A`，其中包含源码、演示视频和报告。报告必须写入公开 Git 仓库链接并保留完整提交记录。

## 2 范围与优先级

### 2.1 必须完成

- 从一个或多个 macOS 网络接口实时捕获数据包。
- 支持可配置抓包长度，默认捕获完整数据包。
- 支持 BPF 捕获过滤以及捕获后显示过滤。
- 解析 Ethernet II、ARP、IPv4、IPv6、ICMP、ICMPv6、TCP 和 UDP。
- 提供数据包列表、协议字段树和 Hex/ASCII 三栏界面。
- 支持绝对时间、异步 DNS 反向解析、列排序、隐藏和宽度调整。
- 支持保存和打开 PCAP 文件。
- 捕获和解析过程不得阻塞 GUI，不得因截断包或畸形包崩溃。

### 2.2 重点完善的 NPA 功能

- 解析 DNS、DHCP、HTTP 和 TLS 握手元数据。
- TCP 五元组双向流追踪、状态识别、RTT 估计、重传和乱序检测。
- IPv4 分片、IPv6 Fragment Header 和 TCP 字节流重组。
- 协议字段与原始字节双向高亮。
- 流量统计、协议分布、Top 主机、Top 端口和 TCP 时序图。
- 两个数据包的字段级与字节级对比。
- 基于明确规则的异常提示，不将提示描述为完整入侵检测。

### 2.3 暂不纳入本阶段

- HTTPS 应用数据解密。
- Wi-Fi 监听模式及其他设备无线帧捕获。
- macOS 进程与网络连接关联。
- Wireshark 源码、插件或 extcap 集成。
- eBPF、XDP 或内核扩展抓包。

这些方向保留为后续扩展，不影响本次实验验收。

## 3 总体架构

```text
多个 libpcap 捕获会话
        ↓
每接口捕获工作线程
        ↓
时间戳归并与重复包检测
        ↓
有界数据包队列
        ↓
基础协议解析与数据包仓库
   ↙          ↓           ↘
Qt 数据模型   流与重组引擎   统计和规则分析
   ↘          ↓           ↙
 数据包列表、协议树、Hex、流视图和统计视图
```

系统划分为以下模块：

1. `capture`：接口枚举、libpcap 会话、BPF、捕获线程及统计。
2. `packet`：不可变原始数据包、基础元数据和数据包仓库。
3. `protocol`：分层解析器、字段模型、校验和及重组入口。
4. `analysis`：流追踪、统计、异常规则、反向 DNS 和数据包对比。
5. `ui`：Qt 数据模型、主窗口、协议树、Hex、图表和交互动作。

模块之间通过明确的数据结构和只读结果通信。捕获线程不得直接访问 Qt 控件；GUI 只消费批量发布的数据和分析结果。

## 4 多网卡捕获设计

macOS 没有 Linux `any` 伪接口，因此每张选中网卡创建一个独立 libpcap 会话。每个会话拥有自己的捕获线程，并将带有接口标识和时间戳的数据包写入共享有界队列。

归并器在一个短时间窗口内按时间戳排序，再写入统一数据包仓库。由于同一报文可能同时出现在物理接口、桥接接口或虚拟接口上，重复包检测使用短时指纹：接口方向、捕获长度、原始长度、时间窗口以及包内容哈希。被判定为重复的包默认合并，并记录曾在哪些接口出现；用户可以关闭去重。

默认接口选择策略如下：

- 优先展示处于 UP 状态且拥有有效地址的物理或常规接口。
- 默认不选择 `utun`、VPN、代理和其他隧道接口。
- `lo0` 单独标记为回环接口，可手动加入。
- 用户可以选择一个或多个接口，软件不擅自捕获全部接口。

可配置捕获参数包括混杂模式、抓包长度、读取超时、内核缓冲区大小和 BPF 表达式。抓包长度默认使用足以保存完整数据包的最大值。暂停只暂停界面更新时仍继续捕获会造成语义混淆，因此本项目将“暂停”定义为停止向 libpcap 获取新包；恢复后继续同一会话，如后端不支持可靠恢复则重新创建会话并显示分段标记。

## 5 数据模型与内存策略

`PacketRecord` 保存序号、绝对时间戳、接口集合、捕获长度、线上长度、原始字节、基础协议摘要、流标识和分析警告。原始字节一经写入即不可修改。

协议解析结果使用树形 `ProtocolNode` 表示。每个 `ProtocolField` 包含名称、原始值、解释值、字节偏移、位偏移、长度、校验状态和警告。该模型同时服务协议树、Hex 高亮、导出和数据包对比。

默认最多保留 100000 个数据包，用户可以调整。达到上限后使用环形淘汰策略删除最早的数据包，同时清理相关索引和过期流。捕获线程到仓库之间使用有界队列；队列满时记录应用层丢包数并在状态栏明确提示，不允许无限制增长内存。

基础字段在数据包进入仓库时解析，以支持列表和过滤。完整字段树在数据包首次被选中、导出或参与详细分析时按需生成并缓存。GUI 每 50 至 100 毫秒批量插入新行，图表每 500 毫秒刷新一次。

## 6 协议解析设计

### 6.1 链路层与网络层

- Ethernet II：源和目的 MAC、EtherType、VLAN 标签。
- ARP：操作类型、发送方和目标 MAC/IP、地址映射提示。
- IPv4：所有首部字段、Options、首部校验和、分片信息。
- IPv6：基础首部及 Hop-by-Hop、Routing、Fragment、Destination Options 等扩展头。
- ICMP/ICMPv6：类型、代码、校验和、Echo 标识及常见错误消息。

### 6.2 传输层

- TCP：端口、序列号、确认号、首部长度、全部 Flags、窗口、校验和、Urgent Pointer 和 Options。
- UDP：端口、长度、校验和。
- 校验和验证需要考虑抓包卸载导致的伪失败；软件会将可疑结果标记为“可能受 checksum offload 影响”，不直接判断为网络错误。

### 6.3 应用层

- DNS：查询和响应、Flags、Question、常见 Resource Record、压缩域名与错误码。
- DHCP：消息类型、事务 ID、地址字段、客户端标识和常见 Options。
- HTTP/1.x：请求行、状态行、Headers、Content-Length、Transfer-Encoding 和载荷摘要。
- TLS：Record、Handshake、ClientHello、ServerHello、SNI、ALPN、版本、Cipher Suites 和可获得的证书元数据。
- 未知协议：显示载荷长度、熵的基础指标、可打印文本和原始字节，不猜测不存在的语义。

协议识别先使用标准端口，再使用内容特征验证。端口与内容冲突时显示“启发式识别”，避免将所有 80 端口流量直接判定为 HTTP。

### 6.4 重组

- IPv4 分片按源地址、目的地址、协议和 Identification 聚合。
- IPv6 分片按源地址、目的地址和 Fragment Identification 聚合。
- TCP 流按规范化五元组聚合，分别维护两个方向的序列空间。
- 重组处理乱序、重传、重叠、重复段、缺口、FIN、RST 和超时。
- HTTP 和 TLS 只在连续 TCP 字节可用时进行跨包解析；存在缺口时显示不完整原因。

重组状态设置每流内存上限、全局内存上限和超时。复杂或畸形输入不得阻塞其他流。

## 7 过滤设计

捕获过滤直接使用 libpcap 的 BPF 编译器。界面提供输入框、语法验证、历史记录、收藏和快捷按钮。快捷项包括 HTTP、TLS、DNS、TCP、UDP、IPv4、IPv6、ICMP 和 ARP。

显示过滤采用本项目自己的表达式求值器，支持：

- 字段比较，例如 `ip.src == 192.168.1.1`。
- 协议存在性，例如 `tcp` 或 `dns`。
- 数字和字符串比较。
- `and`、`or`、`not` 与括号。
- 自动补全、错误位置提示、历史记录和保存常用条件。

显示过滤只影响当前视图，不删除仓库中的数据。过滤在后台执行；新的过滤条件生效前保留旧结果，避免界面闪空。

## 8 DNS 反向解析与代理绕过

反向 DNS 在独立线程池中异步执行，使用带 TTL 的正负缓存。数据包列表先显示 IP，解析成功后仅更新对应显示单元格。排序和过滤仍以原始 IP 为准，避免主机名变化影响结果。用户可以全局关闭反向解析。

抓包本身由 libpcap 直接读取网络接口，不经过 HTTP/HTTPS 代理。本项目不会为分析功能主动发送 HTTP 请求。用于演示的测试流量必须显式绕过本机代理，例如使用 `curl --noproxy '*'`，并优先在实际默认网络接口上捕获。默认不选择 `utun` 等代理或 VPN 隧道接口，但用户可手动选择以研究其流量。

## 9 GUI 与交互设计

### 9.1 主界面

主窗口采用可调整大小的三栏布局：上方数据包列表，中部协议字段树，下方 Hex/ASCII 查看器。侧边或独立标签页提供捕获接口、TCP 流、统计和异常视图。窗口使用低饱和度协议着色，确保浅色和深色主题下均可读。

默认协议颜色建议：TCP 淡蓝、UDP 淡紫、DNS 淡黄、HTTP 淡绿、TLS 蓝灰、ICMP 淡红、ARP 淡橙、异常包浅红。颜色规则可在设置中修改、启用和排序。

### 9.2 数据包列表

默认列为序号、绝对时间、接口、源地址、源端口、目的地址、目的端口、协议、长度和摘要。用户可以排序、隐藏、重新排列和调整列宽，配置需要持久化。

附加功能包括：

- 标记数据包和添加备注。
- 复制地址、端口、摘要或整行。
- 从当前数据包创建捕获或显示过滤器。
- 打开所属 TCP 流或相关 DNS 会话。
- 自定义着色规则。

### 9.3 协议树

协议树显示原始值、解释值、长度、校验状态和异常。点击字段会高亮其原始字节；在 Hex 视图选择字节会反向定位包含该范围的最具体字段。TCP Flags 按位展开，未知或未解析载荷仍保留节点。

协议树可以导出为纯文本和 JSON。导出内容注明解析器版本、数据包序号和原始时间戳。

### 9.4 Hex/ASCII 查看器

每行显示 16 字节，包含偏移、十六进制和 ASCII。不可打印字符显示为点。支持复制、十六进制搜索、文本搜索、跳转偏移、选择范围导出和整数解释。

不同协议层使用细微背景色表示字节归属。整数解释面板显示选中 1、2、4 或 8 字节的大小端无符号值和有符号值。数据包对比支持并排显示、不同字节高亮和字段树差异列表。

## 10 TCP 流与统计

TCP 流使用方向无关的规范化五元组标识，并保存两个方向的数据。状态机识别握手、已建立、半关闭、正常关闭、重置和超时。分析指标包括包数、字节数、持续时间、吞吐率、RTT、重传、乱序、重复 ACK 和零窗口事件。

流视图提供：

- 双向包列表和颜色区分。
- SYN、数据、ACK、FIN、RST 时序图。
- 重组后的文本、Hex 和原始方向切换。
- 单流 PCAP 导出。
- 从流生成过滤器。

统计视图提供总包数、总字节数、当前包速率、当前字节速率、协议占比、包长分布、Top 主机、Top 端口和 Top TCP 流。所有图表使用批量快照刷新，不直接遍历正在变化的数据结构。

## 11 异常提示

异常分析采用透明规则并展示触发原因。首批规则包括：

- 单源在短时间内访问大量目的端口，提示疑似端口扫描。
- 大量 SYN 无对应握手完成，提示异常半连接活动。
- TCP 重传率或重复 ACK 比例异常。
- 明文 HTTP 中出现可疑认证字段，仅显示字段名称，不主动保存或突出敏感值。
- 畸形长度、校验和异常、异常分片重叠或解析不一致。

这些结果只能称为“提示”或“观察”，不能声称已经确认攻击。每条规则提供阈值、统计窗口和关闭选项。

## 12 PCAP 与导出

软件支持实时捕获保存、当前会话另存、打开 PCAP、导出选中包和导出单流。第一阶段以经典 PCAP 为必做格式；PCAPNG 作为扩展，在不影响核心功能时加入。

导出选中包需要保留原始时间戳和捕获长度。打开大文件时增量加载并显示进度，取消加载不能破坏当前会话。导出报告数据支持 CSV、协议树 JSON、统计图 PNG 和流时序图 PNG。

## 13 错误处理与权限

所有字节访问必须先检查剩余长度。截断包显示“数据不足”，畸形包显示具体字段错误，单包解析失败不得终止捕获线程。libpcap 错误、接口消失、权限不足和磁盘写入失败都通过状态栏和可复制的错误详情呈现。

开发和演示阶段从终端以必要权限运行。程序启动时先尝试打开接口；权限不足时显示针对 BPF 设备的说明，不永久修改 `/dev/bpf*` 权限，也不静默请求或保存管理员密码。若后期制作 `.app`，权限辅助程序单独评估，不作为核心验收条件。

## 14 测试设计

### 14.1 单元测试

- 使用固定字节数组测试每个协议解析器。
- 测试正常、截断、畸形、边界长度和未知类型。
- 测试校验和、过滤表达式、字段偏移和格式化。
- 测试 TCP 序列号回绕、乱序、重传和缺口。
- 测试多接口归并及重复包指纹。

### 14.2 PCAP 回归测试

仓库保存不含敏感信息的小型 PCAP 样本。对每个样本记录预期协议、字段、流数和警告。解析输出使用稳定 JSON 快照检查，必要时与 Wireshark 输出人工对照，但不把 Wireshark 作为运行时依赖。

### 14.3 集成与性能测试

- 使用 `ping` 生成 ICMP 流量。
- 使用 `dig` 生成 DNS 流量。
- 使用显式绕过代理的 `curl` 生成 HTTP/TLS 流量。
- 使用本地 HTTP 服务和 `lo0` 验证回环捕获。
- 使用重放或预生成 PCAP 测试高速输入、内存上限和 GUI 响应。

性能结果至少记录持续时间、输入包数、应用层丢包数、libpcap 丢包数、峰值内存和 GUI 是否可交互。

## 15 实施顺序

1. 建立 CMake、Qt、libpcap 和测试框架，完成最小窗口与单接口捕获。
2. 完成数据模型、基础协议解析、三栏 GUI、BPF 和 PCAP 读写。
3. 加入多网卡归并、异步反向 DNS、显示过滤和全部界面扩展。
4. 加入应用层协议、分片/TCP 重组、流追踪、统计和异常提示。
5. 完成压力测试、错误处理、报告素材、演示脚本和提交打包。

预计基础可运行版本需要 6 至 8 天；全部重点 NPA 功能再需要 3 至 5 天。若时间受限，首先保证 NPS、基础协议、过滤和三栏界面稳定，然后按 HTTP/TLS、TCP 流、重组、异常提示的顺序处理高级功能。

## 16 暂留规则

高级功能只有在以下条件同时满足时才可标记暂留：已经完成接口和数据模型；存在可复现失败样本；问题与尝试已记录；不影响基础捕获、解析和 GUI 稳定性。不得用空按钮、假数据或静默失败冒充已实现。

暂留优先级从低到高依次为完整 HTTP 正文重组、TLS 证书深度解析、PCAPNG、大文件增量优化、复杂 IPv6 分片边界。基础协议解析、多网卡捕获、BPF、三栏 GUI、字段联动和 TCP 五元组流追踪不可暂留。

## 17 验收标准

- 用户可以选择至少两张可用接口并开始、暂停、恢复和停止捕获。
- 默认完整抓包，可修改抓包长度，配置错误有明确提示。
- 基础协议及 DNS、DHCP、HTTP、TLS 可以在协议树中显示关键字段。
- 捕获过滤和显示过滤均支持逻辑表达式及错误反馈。
- 列表显示绝对时间和异步反向 DNS，支持排序、隐藏、重排和列宽调整。
- 协议树与 Hex 双向联动；搜索、复制、导出和对比可用。
- TCP 流可双向聚合并展示状态、统计和时序图。
- 软件在畸形或截断 PCAP 上不崩溃，在达到内存上限后保持可用。
- 测试流量默认绕过代理并从实际默认网络接口产生。
- 演示视频展示编译、权限、捕获、过滤、协议分析、流追踪、统计和 PCAP 操作。
